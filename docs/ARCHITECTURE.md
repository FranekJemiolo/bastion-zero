# Architecture

```
iosApp (SwiftUI host) ──┐
androidApp (Activity) ──┤──►  shared (Kotlin Multiplatform)
                        │      ├─ commonMain: UI, mesh logic, crypto API, CRDTs, DB, (Phase 3-4 interfaces)
                        │      ├─ androidMain: SQLDelight Android driver, (Phase 2-4 Android drivers)
                        │      └─ iosMain: SQLDelight native driver, ComposeUIViewController, (CoreBluetooth/CoreMotion)
                        └──►  data_pipeline (Python, build-time only)
```

## Package map (`com.bastionzero`)

| Package | Responsibility |
| --- | --- |
| `mesh` | `LamportClock`, `PacketSigner`, `ReplayGuard`, `PacketValidator` |
| `crypto` | `Ed25519` interface, libsodium implementation |
| `crdt` | `LwwElementSet`, `MapPinStore` |
| `db` | SQLDelight schema, `WikiRepository`, `DatabaseDriverFactory` (expect/actual) |
| `proto` | Generated by Wire from `survival_packet.proto` |

## Decisions in short

See [JOURNAL](JOURNAL.md) for the reasoning behind each.

- Wire for protobuf (true KMP, no JVM-only protoc output).
- libsodium bindings for Ed25519 behind an interface.
- SQLDelight instead of Room KMP (mature on iOS, simple `expect/actual` driver).
- FTS4 rather than FTS5 for Android compatibility.
- Shared Compose UI first; native SwiftUI only where hardware needs it.
